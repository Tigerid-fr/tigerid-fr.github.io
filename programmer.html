Bloc de Compétences 3

Créer des outils et applications informatiques pour les R&T

Démarche réflexive et analytique sur le développement de scripts d'automatisation avancés, la création d'applications Web connectées à des bases de données et la gestion de projets collaboratifs.

AC23.01 // Automatisation & Scripting Système

Automatiser l'administration système avec des scripts

  • Ce que j'ai fait : Développement de scripts en Python et Bash pour automatiser le déploiement de configurations, la sauvegarde de fichiers de journaux et la supervision d'hôtes réseau.
  • Pourquoi je l'ai fait : Pour s'affranchir des manipulations manuelles répétitives et garantir une réactivité immédiate face aux incidents d'infrastructure.
  • Comment je l'ai fait : Utilisation de bibliothèques standard Python, de structures conditionnelles, de fonctions de journalisation et de boucles d'exécution planifiée (cron).
  • Mes difficultés : Gérer proprement les codes de retour d'erreurs et les exceptions lors d'appels SSH distants automatisés.
  • Ce que j'en ai appris : L'automatisation fiabilise les processus d'exploitation et réduit considérablement l'erreur humaine en environnement de production.
  • Ce que je ferais autrement : Modulariser davantage le code sous forme de fonctions réutilisables dès le démarrage du script.

AC23.02 // Développement Web Applicatif

Développer une application à partir d'un cahier des charges donné, pour le Web

  • Pourquoi je l'ai fait : Pour proposer des interfaces de consultation et d'administration ergonomiques, connectées à des services dorsaux.
  • Comment je l'ai fait : Structuration des routes Flask, templating avec Jinja2, gestion des sessions utilisateurs et design responsive orienté composants.
  • Mes difficultés : Maintenir une séparation claire et propre entre la logique métier du serveur et l'affichage des templates côté client.
  • Ce que j'en ai appris : Le développement d'applications Web exige une structure rigoureuse des routes et des données pour garantir la maintenabilité.
  • Ce que je ferais autrement : Intégrer un système de tests unitaires (PyTest) pour valider les routes du serveur web avant le déploiement.

AC23.03 // Protocoles & Programmation Client/Serveur

Utiliser un protocole réseau pour programmer une application client/serveur

  • Ce que j'ai fait : Développement de scripts de communication réseau basés sur les sockets TCP/IP en Python, implémentation de requêtes HTTP/API personnalisées et analyse des échanges applicatifs.
  • Pourquoi je l'ai fait : Pour comprendre concrètement la couche Application et le mécanisme d'encapsulation des données à travers les sockets bas niveau.
  • Comment je l'ai fait : Utilisation des modules Python socket et requests, gestion des flux d'écoute sur des ports dédiés et sérialisation de données.
  • Mes difficultés : Gérer correctement la fermeture des sockets et le blocage des flux d'E/S en cas de perte de connexion du client.
  • Ce que j'en ai appris : Tout protocole réseau repose sur un automate d'états strict qu'il faut programmer fidèlement côté client et côté serveur.
  • Ce que je ferais autrement : Utiliser des threads ou de l'asynchrone pour permettre au serveur de traiter plusieurs connexions simultanées sans latence.

AC23.04 // Gestion & Modélisation de Données

Choisir les mécanismes de gestion de données adaptés et argumenter ses choix

  • Ce que j'ai fait : Conception de modèles conceptuels de données (MCD/MLD), création de bases de données relationnelles sous PostgreSQL / MySQL et écriture de requêtes SQL complexes.
  • Pourquoi je l'ai fait : Pour assurer la persistance, l'intégrité et la rapidité d'accès aux informations manipulées par les applications et outils R&T.
  • Comment je l'ai fait : Normalisation des tables, gestion des clés primaires/étrangères, indexation et connexion des scripts Python aux SGBD via des connecteurs adaptés.
  • Mes difficultés : Établir des relations de cardinalité complexes sans dupliquer l'information et optimiser les temps de réponse des requêtes de jointure.
  • Ce que j'en ai appris : Une base de données rigoureusement modélisée est le garant absolu de la fiabilité d'une application informatique.
  • Ce que je ferais autrement : Valider le modèle relationnel auprès de mes pairs avant d'injecter des volumes importants de données de test.

AC23.05 // Environnement Collaboratif & Versioning

Maintenir et sécuriser un environnement de travail collaboratif

  • Ce que j'ai fait : Utilisation avancée de Git et des plateformes GitLab/GitHub pour la gestion de versions, la fusion de branches (feature branching) et la résolution de conflits en équipe.
  • Pourquoi je l'ai fait : Pour sécuriser l'historique du code source, permettre le travail simultané sur un même projet et assurer la traçabilité des modifications.
  • Comment je l'ai fait : Création de branches thématiques, commits descriptifs, pull requests et application de bonnes pratiques de versioning.
  • Mes difficultés : Résoudre des conflits de fusion complexes lors de modifications simultanées sur les mêmes lignes de code par deux développeurs.
  • Ce l'en ai appris : Le versioning est un filet de sécurité indispensable en programmation collaborative ; il discipline l'écriture du code.
  • Ce que je ferais autrement : Utiliser systématiquement des revues de code (Code Review) avant chaque fusion de branche principale.
